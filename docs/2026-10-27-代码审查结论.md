## 一、P0 必须修复

### A. 转换层静默数据损坏

这类问题不会报错，只会让交付的 YOLO 标签悄悄变错，优先级最高。

| 位置 | 问题 | 复现现象 |
|---|---|---|
| `tools/convert/labelme_to_yolo.py` | `imageWidth/Height` 缺失时默认成 `1` | 输出 `0 30.00000 40.00000 40.00000 40.00000`，坐标全错 |
| `tools/core/labelme.py` | 越界坐标不裁剪到 `[0,W]/[0,H]` | 输出 `0 25.05000 0.50000 49.90000 0.50000`，非法标签 |
| `tools/convert/yolo_to_labelme.py` | `--classes` 指向的 yaml 不存在时静默回退成 `["<路径本身>"]` | 其余类别全丢，只剩 class_id 0 贴着假类名 |
| `tools/convert/labelme_to_yolo.py` | `seed` 形参在 batch 循环内被覆盖 | `--seed` 完全失效 |
| `tools/convert/labelme_to_yolo.py` | 未注册 label 静默丢弃；配置 4 类、磁盘 `datasets/yolo/*/data.yaml` 5 类（含 `helmet`） | 重跑即类别 id 错位 |

### B. 中文路径下整批丢图

本机实测：`cv2.imwrite` 写中文路径返回 `False` 且**文件根本不落盘**，`cv2.imread` 返回 `None`。
`ba293c6` 只修了 `runners/mosaic.py`，其余 runner 仍是直读直写。

| 位置 | 后果 |
|---|---|
| `tools/annotate/runners/common.py` | 读图返回 `None` 被跳过、写图失败不报错但 JSON 照写 → 有 JSON 无图片 |
| `tools/annotate/runners/onnx.py` | 覆盖模式同样问题，整批 100% 跳过只打警告 |

### C. 必然崩溃

| 位置 | 问题 |
|---|---|
| `tools/annotate/runners/supervision.py` | `parse_class_ids` 期望 `dict`，调用方传 `labeler.classes`（`list[str]`）→ `--classes person` 与整个 SAM3 链路必崩 |
| `tools/annotate/auto.py` | `args.output.resolve()` 对 `str` 调用 → `--reannotate` / `--detectors-config` 的报错路径必崩并掩盖真实错误 |

### D. 工作流契约脱节

配置写的和代码做的不一致，定时任务里表现为「跑完了但结果不对」。

| 位置 | 问题 |
|---|---|
| `tools/cfg/__init__.py` | 默认入口 `tools/cfg/workflow_config.yaml` 不存在，README 的 `--dry-run` 写法直接退出 1 |
| `tools/cfg/workflow.yaml` | `train_yolo` 指向不存在的 `datasets/yolo/all/data.yaml`（实际是 `0001…0155` 每批一个） |
| `tools/convert/labelme_to_yolo.py` | `save_data_yaml` 只写 `nc/names`，缺 `path/train/val` |
| `tools/cfg/labelme_to_yolo.yaml` | 传 `--ratios`，脚本 argparse 无此参数（exit 2） |
| `tools/cfg/__init__.py` | `stages_only` 用「先出现保留」，项目 cfg 的 stage 被 `workflow.yaml` 覆盖 → `inherit_dataset.yaml` 的「默认 dry-run」失效，实际带 `--apply` 真拷贝 |
| `tools/cfg/workflow.yaml` | `remove_missing` 没传 `--apply`，而脚本默认 dry-run 且只复制不删源 → 阶段完全空转 |
| `tools/cfg/workflow.yaml` | `manual_review` 只是 `echo`，不会停在人工清洗检查点 |
| `tools/cfg/workflow.yaml` | `create_tar_gz` 输入 `archive/latest`，但 `archive.py` 只生成 `<时间戳>_<tag>/` |
| `tools/workflow.py` | `--from-stage` 拼错时全部跳过仍返回 0；`--to-stage` 是组级判断 |
| `tools/cfg/__init__.py` | 未知变量静默保留占位符照常执行；`${latest:glob}` 基准目录不一致且正则不匹配 `<时间戳>_<tag>` |

## 二、P1 建议修改

### 一致性与健壮性

- `tools/annotate/merge.py`：目录不存在或无 JSON 时仍返回 0，workflow 误判成功；`shape["label"]` 直接下标，坏 JSON 会中断整轮。
- `tools/augment/ir_enhance.py`：`as_completed` 后从不调 `future.result()`，worker 异常被吞仍打印「完成」。
- `tools/clean/orphan_json.py`：直接 `unlink`，无 dry-run/`--apply`，与其它 clean 脚本不一致。
- `tools/annotate/runners/multi.py`：打码策略只读 YAML，忽略 CLI `--blackout/--mosaic`。
- `tools/annotate/runners/supervision.py`：不理会 `--apply`（永远写盘），也不落批次目录。
- `tools/annotate/runners/onnx.py`：覆盖模式按类别重复解析同一 JSON（N 类读 N+1 次）。
- `tools/annotate/runners/mosaic.py`：单图编码失败直接 `raise` 终止整批，与其它 runner 策略相反。

### core 复用收敛

AGENTS.md 要求复用 `tools.core`，但业务脚本普遍绕过它：

- LabelMe IO 副本：`tools/merge/inherit_dataset.py`（且吞 `JSONDecodeError`，坏标注静默归 `other`）。
- 图片扩展名第 4 份分叉副本（只 `png/jpg/jpeg`）：`align_labelme.py`、`timestamp_rename.py`、`labelme_to_yolo.py`。
- 矩形归一化三份副本：`fix_labelme.py`、`labelme_duplicate_boxes.py`、`jpg_to_png.py`。

### 性能与磁盘

- `tools/train/archive.py`：`copytree` 把硬链接展开成实拷，归档会把 `datasets/yolo` 整份复制（`datasets/` 共 178 GB）。
- `tools/workflow.py`：每个 stage 的 stdout 全量驻留内存只为抓一行 `OUTPUT_PATH:`；父进程 stdout 未 `reconfigure`，GBK 控制台下 `✔` 会中断整个工作流。
- `tools/annotate/ops.py`：`DEFAULT_MOSAIC_BLOCK` 定义在文件中部且被跨模块 import，违反「`DEFAULT_*` 集中在文件顶部」。

### 死代码与死配置

- `tools/annotate/defaults.py` 的 `DEFAULT_OUTPUT`、`backends/onnx.py` 的 `decoder`、`backends/base.py` 的 `DatasetLike`：全无调用方。
- `tools/cfg/default.yaml` 的 `image_width/image_height`、`paths.cleaned`：全仓库无引用（但 `workflow.md` 称尺寸由它控制）。
